# BLEGO Original UX v13 — решение по результатам этапа 0

Дата: 2026-11-12. Статус: **утверждено владельцем 2026-11-12; приступаем к реализации**. Уточнение владельца: каждый рабочий элемент копируется отдельно; соответствующие кнопки рядом со значениями.

## Основание и выбранный подход

Задание владельца «UX Restoration & Functional Stabilization v1.0» имеет приоритет над старыми документами. Ветка `codex/blego-original-ux-v13` создана от `7de572764e4f09c5b1a542fbec22161bd1be9f42`. Этот коммит содержит всю работу A/D и нативную подготовку Mac; его исторический Mac CI завершился успешно. Визуальный эталон исключительно `6e57eabfb5b51af4475b90686fa580b5ce57e9b0`.

Предлагается восстановить оригинальную разметку отдельных экранов поверх текущих IPC/сервисов. Возврат всего приложения к оригиналу потеряет локальное хранилище и движок метаданных; перенос экспериментальной UX-ветки целиком противоречит требованию визуального эталона. Поэтому эти варианты не предлагаются как допустимые. Из `fdd57e8` и дополнительно найденной `8c9535a` переносим только проверенные фрагменты, с новыми тестами. Ни одна из этих веток не является основанием визуального PASS.

PR №1, main, старые ветки, прежняя ведомость E01–E60 и пользовательские данные остаются сохранены. Новые коммиты только в новой ветке; без merge, force-push, Release и платных сервисов.

## Защита графики

Не менять шесть защищённых CSS-файлов, исходные изображения/логотипы/иконки/шрифты/анимации. Их SHA фиксируется в `../verification/ux-v13/git-audit.json`. Восстановить исходные DOM-классы и структуру карточек, а не создавать новый каркас. Разрешённые изменения ниже касаются разметки/обработчиков и подписей, прямо требуемых заданием.

Новые элементы сначала собираются из `.card`, `.field`, `.input`, `.btn`, `.pill`, `.ph`, `.risk-bar`, `.hrow` и `<details>`. Если понадобится локальный стиль выбора миниатюры или размещения date/GPS, он помещается в отдельный небольшой файл, использует только существующие переменные и документируется по правилу/назначению. Нет изменений глобальных селекторов, палитры, размеров основного окна, sidebar, шрифтов и анимаций.

## Исправления backend, необходимые до приёмки

### Network

- Различать HTTP/HTTPS/SOCKS5/SOCKS5h, сохраняя auth. Для socks5 — локальный DNS, socks5h — удалённый. Фиксированный безопасный IP endpoint; пользователь не задаёт произвольный target URL. Проверка proxy host/IP и результата DNS отклоняет loopback/private/link-local/reserved/service addresses; тестовые локальные прокси доступны только через явную test dependency, недоступную IPC.
- Отдельные безопасные коды auth/TLS/DNS/timeout/cancel/refused/request blocked. Текущий `TRANSPORT_FAILED` недостаточен. Пароли никогда не включаются в текст ошибок, события, clipboard report или журнал.
- Существующие ping/speed: timeout+cancel+ограничение потока; min/avg/spread только из полученных значений; один образец не доказывает jitter. Подпись «TCP connection latency» для нынешнего метода. TTFB и объём учитываются фактически; скорость только по явной кнопке.
- proxycheck.io — кандидат, не автоматически одобренный источник. Проверить текущую официальную документацию, версию API, числовую шкалу и IP привязку. При отсутствии доступа/лимите — Unknown. Исправить воспроизведённое `Number('') → 0` перед переносом адаптера. Не использовать старые heuristic weights в Trust.
- Дополнительные IPQS/Scamalytics/AbuseIPDB — отдельные источники без объединения, только при разрешённом доступе; ключи только через существующее защищённое хранилище/настройки среды, не Git. Платные подключения не активируются.

#### Разделение маршрутов (решение разработчика для проверки владельцем)

`Check proxy` измеряет соединение и HTTPS-запрос IP через snapshot введённого прокси; результат содержит этот маршрут и время запроса, не смешивается с direct diagnostics. Публичный IP и Trust относятся только к этому proxy result. `Measure latency`/`Measure speed` на исходном приборе подписаны **Direct connection**: фиксированные узлы TCP и загрузка напрямую. Ввод/изменение proxy не переподписывает старые direct результаты как proxy measurements. Карточка прокси показывает собственную задержку запроса, не ICMP. После изменения ввода старый результат помечается previous check до следующей проверки. У каждого результата своя дата/маршрут; одновременные операции не перезаписывают чужое состояние. Это минимальное исправление текущей архитектуры, без ложного объединения маршрутов.

### News

- Каталог classic содержит неподтверждённый комментарий «Approved», а тест проверяет только структуру URL. Отобрать прямые официальные тематические feeds после проверки HTTP, содержания и правил использования; Google News fallback не включать без отдельного обоснования происхождения/правил и разрешения конечных ссылок.
- Убрать background timer всех источников; обновлять выбранную тему с coalescing и ограничением частоты даже при repeated Refresh. Быстрое переключение не теряет запрос последней темы и не подменяет её чужим результатом.
- Закрыть private/service адреса и DNS/redirect переходы, ограничить размер/таймаут. Поддержать объявленные XML-кодировки, Atom alternate links, пустой/ошибочный feed не стирает последний успешный набор. Удалять tracking-дубли URL и publication ID, сортировать только достоверные даты, исключать нерелевантные/неактуальные записи.
- Обновление каталога не стирает сохранённые пользовательские настройки/историю; legacy источники сохраняются как данные, но не смешиваются со встроенной тематической лентой. Переиспользовать имеющееся хранилище, без второй БД/таблицы-кэша.

### Photos, FB, persistence

- Новые date/GPS controls сериализуются в существующие explicit операции. Не расширять семантику date на системные даты файлов. GPS=0 допустим. Preset применён только явным выбором, current values показываются для сравнения, не как скрытые новые значения.
- Превью миниатюр через existing authorized file token/read service, без открытия произвольных путей. Blob/bitmap освобождать при удалении/закрытии; чтение ограничено существующим бюджетом.
- Сохранить dirty-only drafts, multi-selection «unchanged», reference permission/hash checks, идемпотентный экспорт и selective retry. Изменение scope не должно восстанавливать старые применённые overrides.
- Проверки FB по публичному доступу сохраняют unknown для официальных санкций. Missing поля при разборе импорта остаются пустыми; правил классификации не придумываем и не запрашиваем в этой работе.

### Точная семантика даты (уточнение после независимой проверки)

Основная операция называется **Date taken**, а не «все даты»: текущая поддерживаемая группа `EXIF:DateTimeOriginal`, `EXIF:OffsetTimeOriginal`, `XMP-exif:DateTimeOriginal`. `CreateDate`, `ModifyDate`, filesystem timestamps и любые невыбранные поля не затрагиваются. В раскрытии «Date fields» пользователь явно выбирает EXIF и/или XMP representations; preview перечисляет только выбранные изменения. Расширение этой fixed allowlist выполняется в существующих policy/writeArgs/verifyTags и operation schema, без произвольных ExifTool аргументов или второго writer. Старые presets без scope сохраняют прежнюю семантику полной группы, явно показываемую при применении.

Timezone имеет три явных состояния: **Keep existing** (по умолчанию), **Set offset** (обязательное значение пользователя), **Remove offset**. Пустое поле при Set offset — validation error; оно не удаляет прежнюю зону. Keep existing сохраняет существующее значение каждого выбранного файла, не подставляет зону ОС/города. Если зоны смешанные или отсутствуют, preview показывает это по каждому файлу. Remove offset удаляет только offset выбранных представлений даты. При Keep date вся группа сохраняется; при Remove date удаляются только явно выбранные date representations. Эти решения предотвращают скрытое удаление зоны при вводе новой даты и будут проверены отдельно.

## План коммитов и проверки

0. Аудит/скриншоты/карта/этот документ. Утверждение перечисленных минимальных изменений перед продуктовым кодом.
1. Original components/navigation/copy: визуальные пары и состояния loading/hover; запуск всех regression suites.
2. Network transport/error/cancel/measurement/provider: контрольные HTTP/HTTPS/SOCKS5/SOCKS5h с/без auth; реальный внешний маршрут отдельно; реальные provider responses отдельно от fixtures; security/error tests + GUI + regression.
3. News: по каждой теме source counts/HTTP/unique/current/displayed/last success; RSS/Atom/redirect/private/cache429/cancel/race tests; реальные feed проверки + GUI + regression.
4. FB: single/multiline/link/copy/progress/cancel; fixtures объяснимых ответов и отдельная ограниченная live проверка без bypass + regression.
5. Photos: single/group date/GPS JPEG/PNG/WebP, actual readback, content/alpha/ICC/orientation/original hash, no overwrite/cancel/permission/full-disk/restart; GUI от выбора до копии + regression.
6. Generator/Archive: female generator/uniqueness/exhaustion/saved prefs/history; все архивные действия с подтверждением удаления; original card comparison + regression.
7. Полная приёмка нового SHA: lint/unit/integration/GUI, screenshot/animation comparison, native ARM64 runtime probe, DMG, mounted/installed outside-checkout app, SHA256, signing/notarization state, Mac timing measurements, инструкция и список ограничений. Без merge/Release.

Подготовка к нативной проверке сохраняет существующий Mac workflow и gate: новый кандидат проверяется на настоящем ARM64 runner. Linux не может дать Mac PASS. Новые платные тарифы не подключаются; при недоступной разрешённой среде/бюджете native gates BLOCKED. Стоимость существующих Actions запусков/лимит нужно установить до нового запуска; само наличие старого success не доказывает доступный бюджет.

## Что уже проверено и чего это не доказывает

Подробности: `../verification/ux-v13/AUDIT.md`, `FUNCTION_MAP.md`, JSON и журналы. Linux повторно: 42 unit, 71 integration, 3 GUI. Снимки четырёх refs с одинаковым viewport/theme. Существующий metadata backend реально записывает date/GPS в synthetic JPEG/PNG/WebP с readback, но новый удобный экран ещё не реализован. Контрольные локальные proxy transports работают; публичный внешний IP через пользовательский proxy и real provider Trust пока не приняты. Все старые ограничения словарей/FB/classification сохраняются явными.

Статусы этого документа — предложения и baseline evidence, не заявление о выполнении этапов 1–7.

Независимая builder-проверка 2026-11-12 выявила два существенных пробела: смешение direct/proxy измерений и смысл пустого timezone. Они закрыты явными решениями выше; эти решения входят в дизайн, одобренный владельцем перед началом реализации.

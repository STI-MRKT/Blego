# BLEGO 1.4 comparison method

Baseline 1.3: `782c1b2c1b61703f81542eafb8d97a33fc3264ec`. Original graphics reference: `6e57eabfb5b51af4475b90686fa580b5ce57e9b0`. Candidate is the current v1.4 branch. Results in adjacent JSON are observations, not universal throughput promises. Native reports will identify the exact tested commit.

`check-ux-performance.cjs`: three isolated launches per version in one environment, generation and (baseline13/candidate) identical 1000-row synthetic CSV. Identical fixed renderer viewports for screenshots; this is distinct from native window-bounds tests. Linux headless frames were ~50ms for all versions, so these numbers do not establish physical-display animation smoothness. Linux candidate startup 401–611ms; generation 154–165ms; import 219–227ms. Baseline13 startup 452–813ms, generation 131–361ms, import 167–242ms. Small samples and shared-host scheduling limit inference.

`check-real-photo.cjs`: actual public Fronalpstock panorama by Hannes Röst, CC BY-SA 3.0, source https://commons.wikimedia.org/wiki/File:Fronalpstock_big.jpg and license https://creativecommons.org/licenses/by-sa/3.0/. Pinned original SHA-256 `24eb29eccdf0af691b406d1a3d22c0ef5d761cc454d8a917848c33958f6fc857`. Original is above the application's 40MP limit, so the QA harness (not the application) produces 6000×2696 JPEG/PNG/WebP derivatives before timing. Same byte-identical inputs for both versions; public fixtures and derivatives are not bundled with BLEGO or committed to Git. Reports record their hashes/sizes. Explicit date/GPS export, independent ExifTool readback, unchanged source hashes and decoded pixels. Sequential isolated processes; one sample each. Linux baseline total11.17s/export5.59s, candidate total10.10s/export4.95s; parent Node peak RSS ~511/512MiB respectively, not total process-tree memory.

`check-metadata-load.cjs`: actual 1/10/100/500/1000 synthetic image read/export/readback plus synthetic 12MP images; generated GPS quantized uniqueness and polygon inclusion checked. Do not equate tiny fixtures with real-photo throughput. Baseline13/candidate manual 1/10/100 comparison uses identical operations; 500/1000 exceed baseline13's supported queue and have no valid old-version comparison.

`check-metadata-ui-batch.cjs`: real Electron chooser→read→explicit GEO/date→preview→save, folder hierarchy and output existence. Linux100-folder sample: 46.35s total, max observed renderer event-loop gap144ms. The installed Mac run additionally exercises1000 files; 25ms timer gaps describe observed responsiveness, not frame rate. Native full engine workload separately verifies every output's values/pixels.

No signing credentials, actual owner confidential TXT files, authorized Meta API access or owner-supplied external proxies have been used. These are separate gates, never inferred from synthetic tests.

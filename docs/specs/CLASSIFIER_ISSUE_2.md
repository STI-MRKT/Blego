## 1. Главное задание: предметный классификатор синтетических записей

Сейчас `shared/importer.mjs` парсит TXT/CSV/TSV/JSON, но `electron/features/classification/service.cjs` при отсутствии тестовых правил возвращает `rules_pending`. Нужно добавить **рабочую продукционную схему классификации** для импортированных синтетических записей. Результат — фиксированные 11 колонок:

`№ | ФИО | ID | Пароль | Пароль от почты | Почта | Дата рождения | ГЕО | User-Agent | Токен | Куки`

Ключи: `rowNumber, fullName, accountId, password, emailPassword, email, birthDate, geo, userAgent, token, cookies`.

Для каждой логической записи — стабильный `recordId` и порядковый номер. Нельзя терять, объединять или смешивать соседние строки при пропущенных полях.

### 1.1. Входные форматы и алгоритм

- Текущие TXT/CSV/TSV/JSON продолжать поддерживать. Добавить headerless TSV и известные схемы колонок; `|` и `;` учитывать вне кавычек/JSON; пустые позиции **сохранять**.
- Многострочный корректно экранированный JSON внутри одной строки не дробить по запятым или переводам строк; сложный формат не угадывать по разделителю внутри значения.
- Определять значения в приоритетном порядке: явные названия полей → подтверждённая схема файла → явный пользовательский выбор соответствия колонок → осторожные эвристики. При спорных случаях **не приписывать значение соседнему пользователю и не выдумывать значения**; оставить пустым и показать возможность уточнить.
- Email, даты (DD.MM.YYYY, DD/MM/YYYY, YYYY-MM-DD), GEO и User-Agent распознавать по структуре. ID хранить строго **как строку** с ведущими нулями; никогда не округлять через JS Number.
- Различать `password` и `emailPassword` по явному ключу/схеме; меньшая длина, цифровой суффикс или `!` — **подсказка, но не достаточное основание**.
- Строки, похожие на токены, выделять отдельно только при подтверждённой схеме или явном поле. Не проверять токены на действительность.
- Cookie JSON может содержать несколько объектов, длинные строки и escaped characters. Сохранять исходное **точное представление** как строку, не пересобирать посредством `JSON.stringify`, если это меняет исходные байты. Cookie принадлежат **строке исходного файла**, не определять принадлежность по совпадению чужого `c_user`; при конфликте — предупреждение, но не перенос.
- Для непонятных полей сохранить локальное нераспознанное значение/исходный диапазон, не смешивать с основными полями.

### 1.2. Таблица и копирование

- Использовать **оригинальный дизайн BLEGO**: существующие `.tbl`, `.copy`, карточки, анимации, тёмную палитру; не менять графику, `tokens.css`, общую навигацию. Только локальные минимальные правки.
- Визуальный порядок 11 колонок фиксирован, горизонтальный прокрут, строки компактные, до 50 строк на страницу.
- Длинные `User-Agent`, `Токен` и `Куки` показывать сокращённо (примерно 10–15 видимых символов + многоточие), без полного текста в DOM атрибутах/tooltip.
- **Cookie — значок копирования непосредственно в ячейке. Одно нажатие копирует ПОЛНОЕ исходное значение только этой строки**; без промежуточного диалога, открытия панелей, раскрытия строки. После успеха — краткая стандартная обратная связь. Не использовать собственный обход системного буфера: текущий `copyText` и IPC уже есть.
- Главные массовые действия (`Копировать строку`, `Копировать таблицу`) используют **только 7 полей**: ФИО, ID, основной пароль, пароль почты, почта, дата рождения, ГЕО. Cookie, User-Agent и Токен в эти операции не входят и не попадают в TSV/CSV по умолчанию.
- Копирование отдельной ячейки точно, сохранены все символы; кнопки для пустых значений отключены. Сортировка/фильтрация/пагинация не нарушают соответствие `recordId → значение`.
- Существующий адаптер `shared/copy-sources.mjs` защищает чувствительные поля при массовом копировании. **Не ослаблять защиту глобально**. Добавить отдельную, явно управляемую пользователем модель копирования именно для семи согласованных полей классификатора. Изменения чувствительных данных только по явному пользовательскому действию; в журналах/аналитике их быть не должно.
- Защита TSV/CSV от выполнения формул должна сохраняться без изменения исходной памяти.

### 1.3. Ресурсы и безопасность

- Разбор локальный, без сетевых запросов, без аутентификации, без проверки реальных Facebook сеансов.
- Использовать существующий worker, ограничения 50 MiB, отмену и пагинацию. Не создавать все DOM-строки сразу.
- Не записывать cookie, токены или пароли в журналы/артефакты CI/скриншоты. Тесты — **только полностью фиктивные** `FAKE_COOKIE_...`, `example.com`, токен-имитации.
- Никаких новых постоянных хранилищ секретов без отдельного согласования. При очистке импорта сбрасывать связанную с ним память.
- Без мнимых результатов: `rules_pending` должен замениться реальным статусом классификации только когда применены и проверены продукционные правила.

## 3. Минимальная матрица проверок

Создать модульные + интеграционные + UI тесты на полностью вымышленных наборах:
1. Известная headerless TSV-схема с пустыми табуляциями, нормальными именованными заголовками, многострочный JSON/CSV.
2. Несколько записей, стабильный номер, ID > 2^53 и с ведущими нулями.
3. Разделение password/emailPassword; сомнительный случай без автоматического угадания.
4. ФИО, email, даты (включая невозможную), GEO, User-Agent, синтетический токен.
5. Cookie JSON и текст 12/1000/10000 знаков: UI обрезан; в clipboard полное значение, **строка строго соответствует `recordId`**. Пустая cookie → кнопка недоступна.
6. Копирование **всех** и только 7 основных полей в TSV/CSV; cookie/token/UA никогда не добавляются в массовое копирование. Отдельное копирование по кнопке без обрезки.
7. Классические regression тесты `npm run verify`, текущие GUI suite. Макет интерфейса сравнить со снимками оригинального генератора, исходные графические активы не менять.
8. На настоящем GitHub-hosted `macos-15` (M1): native runtime gate, `npm run dist:mac -- --arm64`, запуск собранного приложения **вне исходников**, UI tests, SHA-256 и upload QA артефакта. Подписанный релиз не выпускать.
9. Отчёт PASS/FAIL/BLOCKED по каждому требованию. Публиковать QA только при полном PASS, не отключать тесты.

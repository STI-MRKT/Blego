# BLEGO v1.2 — план продолжения D8–D14

Фактическое исполнение: [журнал](../verification/UNIFIED_12_PROGRESS.md), [новая приёмка E01–E60](../verification/UNIFIED_12_ACCEPTANCE.md). Открытые внешние шлюзы не отмечены как завершённые.

> Для исполнителя: применять `superpowers:executing-plans` либо `superpowers:subagent-driven-development`, если они доступны в рабочем окружении. Шаги выполнять последовательно, с фактическими проверками. Этот документ не разрешает начинать A/D с нуля.

**Цель:** сохранить реализованную базу, добавить ручной групповой редактор метаданных и закрыть оставшиеся шлюзы данных/платформ.
**Архитектура:** существующий Electron, один владелец SQLite, действующие сервисы генератора/архива/clipboard/изображений. Расширение сервиса изображений и его UI вместо второй программы или движка.
**Стек исходного коммита:** JavaScript/ESM+CJS, Electron 45.3.1, electron-builder 26.18.0, встроенная SQLite, ExifTool 13.63, Sharp 0.35.5. Версии сверять с реальным HEAD, не откатывать обновления автоматически.
**ТЗ:** `docs/specs/BLEGO_LOCAL_V1_UNIFIED_12.md`.
**Исходная ветка:** `STI-MRKT/Blego`, `codex/blego-local-v1`, `aeb8c237780088d33a1ac8c2f05549144088d192`.

## Общие ограничения

- Новые значения метаданных задаёт пользователь; автоматическая генерация/геолокация/подстановка из генератора запрещены. Сам генератор синтетических профилей сохранён.
- Исходные изображения, ZIP, база и история уникальности не уничтожаются и не обнуляются.
- Keep / Set / Remove сохраняются; Inherit — только настройка переопределения, не команда записи.
- 100 файлов; 50 МиБ/файл; 512 МиБ суммарно; 40 МП; два тяжёлых worker; 60 секунд/вызов движка; 8 МиБ вывода. Ограничения общие для групп.
- `rules_pending` не превращается в классифицированный результат. Сетевые зависимости не блокируют локальные работы.
- Нативные сборки/подпись/нотариализация требуют своих доказательств; сборки без публикации.
- D0–D7 и E01–E32 — история; новые этапы D8–D14 и сценарии E33–E60 дополняют её.

## Фокус дополнительной проверки

1. Явный Keep на файле должен отменять Set группы, а не наследовать его по ошибке — D8/E35.
2. Смена выделения/шаблона после предпросмотра не должна применить старый план к новым файлам — D10/E37.
3. Отсутствующий тег образца не должен стереть существующий тег назначения — D9/E41.
4. Два worker — на всё приложение, не на каждую группу; 100 файлов — также общий лимит — D10/E36,E49.
5. Встроенный runtime должен работать из установленного пакета без рабочего дерева и системного Perl — D13/E54–E59.

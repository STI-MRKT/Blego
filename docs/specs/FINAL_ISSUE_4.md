## 1. Proxy Checker: два независимых режима + полноценные показатели

Сохранить работающие `electron/features/proxy/transports.cjs`, `service.cjs`, `providers.cjs` и прежнюю анимированную панель `src/js/ui/network.js`; не заменять их новым интерфейсом.

### 1.1. Локальные измерения без коммерческих API
- Поддержка HTTP, HTTPS, SOCKS5 (удалённое разрешение DNS для SOCKS5), с авторизацией и без.
- При явном нажатии Check: проверить соединение и авторизацию, получить внешний IP **через данный прокси**, измерить TCP-задержку, разброс и стабильность повторных HTTPS-запросов. Скорость измерять отдельно или по явно разрешённому полному тесту с лимитом трафика и тайм-аутом.
- Внешний IP требует HTTPS echo-узла (возможна своя конечная точка); это сетевой запрос, хотя он и не является коммерческим API репутации. При недоступности узла — `IP не определён`, не использовать ошибочно локальный IP.
- Отображать состояние соединения, IP, задержку и качество соединения (0–100 **только если** реально измерены достаточные данные). Определить и документировать фиксированную воспроизводимую методику quality score: успешность N попыток, RTT/разброс, скорость по выбранному тесту; при отсутствии измерений — `Недостаточно данных`. Качество сети **не равно** репутации IP.
- Дополнительные локальные признаки — Tor exit list / GeoLite2 ASN / разрешённые открытые базы при наличии лицензии, источника, даты обновления и ручного разрешения на загрузку. Не называть отсутствие совпадения `IP безопасен`. Можно отображать локальные факты отдельно; репутационный числовой показатель без источника риска не выдумывать.

### 1.2. API репутации: основная реализация proxycheck.io v3
Официальная документация: https://proxycheck.io/api/ . На дату ТЗ stable v3; использовать **документированный формат v3**, не устаревшую структуру v2.
- Режим `Репутация IP: по API` — дополнительно, включается по явному согласию пользователя. Получить подтверждённый exit IP и отправить **только IP** на HTTPS endpoint провайдера напрямую (не логин/пароль/хост прокси и не cookie).
- proxycheck.io v3: поддержать бесплатное обращение без ключа (документированный лимит на момент ТЗ 100 запросов/сутки на исходящий IP), пользовательский бесплатный ключ (порядка 1 000/сутки согласно текущей документации). Все лимиты проверять по текущему ответу и документации; никаких обходов лимитов.
- Формировать **Trust Score = 100 − risk_score**, только если провайдер прислал успешный валидный числовой risk score 0–100 по ТОЧНО проверенному выходному IP. UI показывает `Траст: 82/100`, провайдер, время проверки, понятную шкалу и основные признаки. В примере 82 условно. Это **обратная шкала риска данного провайдера, не универсальная гарантия безопасности**.
- НЕ путать поле `risk score` с `confidence score` (у proxycheck.io confidence относится к уверенности детекции).
- Если статус ошибки, HTTP 401/403/429, тайм-аут, неверный ответ, конфликт IP, устаревшая база или отсутствует достаточный сигнал — `Траст не определён`; качество/пинг продолжают работать.
- В будущих настройках провайдера можно предусмотреть адаптер IPQualityScore, Scamalytics и AbuseIPDB, но для приёмки требуется **один полностью работающий** провайдер proxycheck.io v3, а не фиктивная поддержка всех четырёх. Источники не усреднять произвольно. Для других источников показывать отдельные независимые значения и причины при наличии реальных ключей.
- Не включать API-ключ в пакет приложения, renderer, репозиторий, URL журналов и ошибки. Использовать существующее локальное защищённое хранилище/системную связку ключей для ключа, введённого владельцем; отсутствие ключа не блокирует локальные тесты. Для HTTPS-запросов хранить только нужные обезличенные сведения. Функция cache TTL — согласно свежести и правилам провайдера, отображать дату.
- Безопасность транспорта: нормализация и проверка адресов, запрет SSRF/localhost/служебных хостов для пользовательских override, ограниченные тайм-ауты/размеры ответов, проверка TLS, отмена, запрет утечки credentials через URL/отчёты, никаких автоматических запросов при открытии окна.
- Не менять оригинальные графические элементы: анимация скорости, графики пинга, блок сети и исходные карточки должны остаться.

**Гейт:** реальные HTTP/HTTPS/SOCKS5 тесты с тестовыми прокси/локальными фикстурами; отдельные contract tests на ответ proxycheck v3: success, null, malformed, mismatch IP, 401, 429, timeout, отмена; отсутствие скрытой отправки логина/пароля. Реальные внешние проверки — при законном доступе; при недоступности сети/ключа маркировать BLOCKED, не PASS.

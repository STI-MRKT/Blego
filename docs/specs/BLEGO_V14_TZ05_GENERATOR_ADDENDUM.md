# Дополнение к ТЗ №5 — Генератор профилей BLEGO 1.4

## 1. Удаление вкладки «Дополнительные поля»

Полностью убрать раскрывающийся блок «Дополнительные поля» из карточки сгенерированного профиля.

Требования:

- Удалить кнопку раскрытия и соответствующий блок интерфейса.
- Сохранить основные поля карточки, аватар, категории и BIO.
- Не удалять данные из внутренней модели генератора, если они используются другими функциями.
- Сохранить копирование полного набора данных.
- Сохранить согласованные кнопки отдельного копирования имени и BIO.
- Не нарушать адаптивность, оформление и анимации карточки.

При выборе `tech` вместо обычных имён людей генерировать названия технологических проектов, сообществ, компаний или тематических страниц.

Эти 25 примеров включить в базовый пул.

**Дополнительно создать 200–300 новых уникальных названий**, соответствующих технологической тематике.

Направления: Artificial Intelligence, Machine Learning, Robotics, Software Development, Cybersecurity, Cloud Computing, Digital Technology, Automation, Future Technology и Innovation.

Требования к названиям:

- Преимущественно английский язык.
- Естественное, читаемое сочетание 2–3 слов.

- Исключить дубликаты после нормализации регистра и пробелов.
- Не генерировать бессмысленные сочетания слов.
- Не использовать названия известных компаний в качестве заявлений о принадлежности к ним.
- Для `tech` не применять обязательное правило формирования женского имени и фамилии.

## 3. Расширение пулов всех категорий

В текущем BLEGO доступны три категории:

| Категория | Требование |
|---|---|
| `model` | Добавить 200–300 новых уникальных вариантов имён с сохранением принятой логики персональных имён |
| `tech` | Добавить 200–300 новых тематических названий сверх 25 предоставленных примеров |
| `crypto` | Добавить 200–300 новых уникальных вариантов с сохранением существующего стиля категории и криптовалютной тематики |

Новые элементы должны **дополнять существующие наборы**, а не заменять их.

Для `model` сохранить географическую специфику имён по выбранной стране. Для `crypto` сохранить текущую логику именования, дополнив её разнообразными тематическими вариантами. Если текущая категория использует персональные имена, не заменять их названиями проектов без отдельного правила.

Не допускать повторной выдачи одного имени в рамках действующей политики уникальности, если пользователь явно не разрешил повторы.

### Архитектура

Переработать выбор названия в генераторе так, чтобы тип профиля определял стратегию именования:

- `person_name` — персональные имена;
- `brand_name` — тематические названия проектов.

Не привязывать все категории к единственному алгоритму «имя + фамилия». При этом сохранить действующие правила стран, почтовых адресов, идентификаторов и истории генерации.

## 4. Единый учебный домен электронной почты

Для всех новых автоматически генерируемых профилей использовать исключительно:

**`@dayrep.com`**

Примеры:

- `future.hub@dayrep.com`
- `ai.vision@dayrep.com`
- `digital.minds@dayrep.com`
- `esther.reis@dayrep.com`
- `crypto.frontier@dayrep.com`

Требования:

1. Домен одинаковый для `model`, `tech` и `crypto`.
2. Левая часть адреса создаётся из имени или названия с нормализацией символов.
3. Все автоматически генерируемые адреса должны быть уникальными.
4. При совпадении базового адреса использовать контролируемый механизм создания уникального локального идентификатора.
5. Не использовать в новых автоматически генерируемых адресах `example.com`, `example.net`, `example.org`.
6. Не изменять уже сохранённые профили, импортированные пользовательские почтовые адреса и исторические записи.
7. Не отправлять письма и не проверять существование почтового ящика автоматически.

Важное условие: домен рассматривается как заданный пользователем учебный домен; наличие реального почтового ящика не подтверждается генератором.

## 5. Расширение BIO для всех категорий

Добавить **не менее 50 новых уникальных биографий в каждую категорию**.

| Категория | Дополнительные BIO |
|---|---:|
| Model | +50 |
| Tech | +50 |
| Crypto | +50 |
| **Всего** | **+150** |

### Model

Тематики: мода, фотография, стиль, эстетика, путешествия, творчество, красота, повседневная жизнь.

Соблюдать существующую языковую локализацию по странам.

### Tech

Тематики: искусственный интеллект, современные технологии, программирование, инновации, машинное обучение, цифровые продукты, автоматизация.

Примеры стиля:

- Exploring the future of AI and digital innovation.
- Building ideas for a smarter tomorrow.
- Technology, creativity and endless possibilities.
- Discovering new horizons in artificial intelligence.

### Crypto

Тематики: блокчейн, Web3, цифровая экономика, криптовалютные технологии, децентрализованные системы.

Не добавлять гарантии заработка, ложные инвестиционные обещания или заявления о финансовой лицензии.

### Общие правила BIO

- Каждая биография должна быть естественной и тематически подходящей.
- Не использовать 50 почти одинаковых фраз с заменой одного слова.
- Сохранять корректную пунктуацию и локализацию.
- Не создавать дубликаты после нормализации.
- Использовать существующий механизм выбора BIO.
- Сохранять полную биографию при копировании по отдельной кнопке.
- Не изменять ранее сгенерированные профили.

## 6. Обязательные проверки

Codex должен добавить автоматизированные испытания, подтверждающие:

1. Отсутствие блока «Дополнительные поля» в интерфейсе.
2. Сохранность внутренних данных и работы Copy full set.
3. Генерацию названий из нового пула TECH.
4. Отсутствие случайных персональных имён вместо названий технологических проектов при выборе стратегии `brand_name`.
5. Расширение пулов каждой категории на 200–300 записей.
6. Отсутствие повторяющихся названий.
7. Использование `@dayrep.com` для всех новых автоматически генерируемых адресов.
8. Уникальность почтовых адресов даже при совпадении названий.
9. Сохранность ранее созданных профилей.
10. Наличие минимум 50 дополнительных BIO на категорию.
11. Соответствие BIO выбранной тематике и языку.
12. Работу отдельных кнопок Copy Name и Copy BIO.
13. Сохранение существующих функций генератора, архива и классификатора.
14. Корректную массовую генерацию и поведение при исчерпании конечного пула.

После изменений выполнить полный набор unit, integration и GUI-тестов, а также проверить установленную сборку macOS ARM64.

## 7. Ожидаемый результат

Генератор BLEGO 1.4 должен:

- иметь более простой интерфейс без вкладки дополнительных полей;
- создавать тематические названия для TECH;
- содержать значительно расширенные пулы во всех трёх категориях;
- генерировать новые адреса электронной почты с доменом `@dayrep.com`;
- иметь минимум 150 новых тематических BIO суммарно;
- поддерживать копирование имени и биографии по отдельности;
- сохранять предыдущие функции и пользовательские данные.

Реализовать как часть ТЗ №5 в той же рабочей ветке и PR. Отдельный релиз или слияние без пользовательской приёмки не выполнять.

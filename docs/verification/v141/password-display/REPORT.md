# Classifier: отображение паролей

**Проверенный кандидат: `1676e92c8590b7445fbfecb0ae246506459c62df`.** [PR #7](https://github.com/STI-MRKT/Blego/pull/7), [снимок установленного приложения](classifier-passwords-mac.png).

Дополнение пользователя от 13 ноября 2026: «классификатор должен ещё отображать пароли».
База: 7cf1a7c6b6e8e444ab7c2e54b5f85bb7e287eb28, PR #7, чистая рабочая ветка codex/blego-v1-4-1-fixes.

Причина: показанный sample.csv не содержит паролей; независимо от этого заполненные password/emailPassword маскировались в renderer таблицы. Теперь оба поля показаны обычным текстом в существующих колонках. HTML escaping сохранён; исходные значения, распознавание, архивы и семипольный экспорт не меняются. Отдельные кнопки копируют исходное значение. Отсутствующий пароль остаётся пустым; неоднозначное немаркированное значение требует назначения поля, а не угадывания.

Проверки: два существующих GUI-сценария воспроизвели маскирование (RED), затем PASS после одной строки изменения renderer. Дополнены проверки точного вывода/копирования обоих полей, HTML-подобного текста без создания элементов, Unicode и значащих нулей; пустые значения и недоступная кнопка копирования проверены. Старые утверждения о скрытии паролей заменены согласно явному новому требованию; сокрытие нераспознанных исходных полей и явное раскрытие подробностей проверяются по-прежнему. Токены/cookies и отсутствие их в массовом экспорте остаются под существующими проверками.

Linux x64: профильные 3 GUI PASS; lint, 105 unit и 119 integration PASS. Первый снимок ожидал исчезновения одного уведомления через строгий locator, но уведомлений было два: исправлено на ожидание отсутствия всех уведомлений; DOM/анимации не удаляются для снимка. После обычной прокрутки к началу таблицы снимается реальный экран с синтетическими паролями. Сборка и полный GUI зафиксированы ниже.

Предыдущий проверенный пакет b6afdf0 и его отчёты остаются исторической приёмкой; этот исторический пакет не содержит новую правку.

Первый общий Linux GUI: 29 PASS / 1 FAIL в старом сценарии photo-map (ожидание тайлов). Тест заполнял кэш по одному снимку viewport до завершения асинхронного fit/resize. Отсутствующие после смены масштаба тестовые тайлы провоцировали внешний запрос вместо контролируемого raster. Такое же падение воспроизведено явным изменением масштаба после подготовки кэша. Исправлен только fixture: он заполняет временный кэш для фактически запрошенных координат перед исходным IPC handler; штатная валидация отправителя/аргументов, декодирование кэша и Canvas сохранены. Добавлено утверждение, что действительно запрошены тайлы за пределами первоначального набора. Пиксельная проверка (>1000 пикселей заданного цвета) остаётся; ожидает фактическую отрисовку. Контрольный zoom-out оставляет пиксели вне полупрозрачной заливки города, после чего масштаб возвращается. Профильный сценарий PASS. Во время подготовки fixture исправлены недоступный require в main evaluation (использован process.getBuiltinModule) и выбор масштаба для проверки незакрашенных пикселей. Код карты приложения не менялся; первый FAIL сохранён.

Повторная общая проверка Linux: lint PASS, 30 GUI PASS / 0 skipped (130.419 с). Unit 105 и integration 119 PASS из прогона на том же продуктовом коде; затем менялся только тестовый fixture карты и его форматирование. Отдельный снимок паролей и проверка копирования PASS.
